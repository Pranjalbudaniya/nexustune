# BUG-001: Stream URL Expiry & Failure Reporting in ExoPlayer

- Status: RESOLVED
- Severity: P2 (Major)
- Component: `:core:player`, `:core:data`
- Reported By: Failure Injection Suite
- Resolved In: Phase 6 Hardening

## Description
YouTube audio streaming URLs expire after a finite TTL (typically 6 hours, marked by `&expire=` timestamp). When playback was attempted on an expired URL, the underlying media player produced an unhandled `PlaybackException` (HTTP 403 Forbidden or 410 Gone) without propagating human-readable status to `PlaybackState`, potentially freezing the UI in a perpetual buffering state.

## Root Cause
`PlayerController`'s `Player.Listener` implementation lacked an `onPlayerError` listener override, leaving `PlaybackState.status` in `BUFFERING` without notifying the presentation layer of the failure.

## Remediation
1. Implemented `onPlayerError` in `PlayerController.kt` to explicitly capture `PlaybackException` and transition state to `PlaybackStatus.ERROR` with descriptive message.
2. Added `retryWithStream(newStreamUrl: String)` method on `PlayerController` to permit immediate hot-swap recovery of refreshed audio URLs.
3. Added automated unit tests `StreamExpiryRecoveryTest.kt` verifying stream re-resolution and error fallback.

## Verification
- `StreamExpiryRecoveryTest` passes cleanly.
- `./scripts/gate.sh slice` passes cleanly.
